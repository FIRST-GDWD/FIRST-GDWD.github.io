How to Submit Your Coding Assignments

Serving Your Work to Your Instructor

PART 1

Visual Studio Code

Save Your Work!

  1. In order to submit your work, you first have to save it!

    If you see a white circle next to the name of any files in your Visual Studio Code tabs, then you have unsaved work, which will not show up when your instructor looks at it!

    So go into those files, and hit CMD+S or CTRL+S to save them.

    Once you confirm that those circles are gone, you can move on to the next step.

Congrats! Your work is saved on your computer; now it's time to start the process of moving it up to github.com!

PART 2

GitHub Desktop (The App)

Packaging Up Your Code for Delivery

  1. Our next goal is to package up your code so that it can be sent up to github.com.

    To do so, open up GitHub Desktop.

    If you've successfully saved your changes, you should see all the file you modified in the left column labeled "Changes" in GitHub Desktop.

    Confirm that this is the case. If it is not, go back to Part 1!

    NOTE: don't be alarmed if you see red or orange colors in GitHub Desktop; they are not necessarily a bad thing. Red means deletions occurred, and orange means changes occurred. Both are very common, and are only problematic if they are unexpected!

  2. Once you've confirmed that you see the files you expected, we're going to create what is called a "commit". A "commit" is essentially a snapshot of the changes you made, packaged up such that they can be sent to github.com.

    To create a commit, you'll need to fill out the Summary field in the bottom left. This field is meant to be a note to yourself about what changes you included in the commit.

    We recommend including demo or assignment names in your summary messages, like "Created code skeleton" or "fixed bulletin board project".

    Then, once you've filled out the summary field, go ahead and click the blue "Commit" button beneath it.

  3. After hitting the "Commit" button, all your changes will seem to disappear (they aren't actually gone, they've just been moved to the History tab in the new commit you just made).

    Now we need to send that commit up to github.com. We do that through a process called a "push".

    To "push" your code up there, you just need to click one of the two buttons that say "Push origin", either the black rectangular one at the top of the screen, or the round blue one in the middle of the screen.

  4. After that, the push process will run. It usually only takes a couple of seconds, but it can run longer depending on your internet connection, how many changes you pushed, and how large the files you pushed were.

    If this process takes more than 5 minutes and you're still waiting, refer to this troubleshooting page for how to resolve it.

    Then your app should look something like the screenshot to the right.

  5. Now that you've committed and pushed, your code changes should have successfully made it up to github.com, so our next step involves actually going there to find it!

    To do so, simply click the button that says "View on GitHub", which will open a browser window that leads straight to your repository on github.com.

Congrats! You have successfully committed and pushed your code! Now onto github.com to find it!

PART 3

github.com (The Website)

Finding and Submitting Your Assignments

  1. You should now be on your repository on github.com, which should resemble the screenshot on the right.

    Before anything else, you first need to check if your code can even be viewed on your own personal GitHub Pages website.

    To do so, click on the link in the bottom right to the Deployments page.

  2. The Deployments page (should) list out all your recent commits, along with their deployment status.

    You want to confirm that you see your latest commit summary, along with a green checkmark next to it at the top of the list.

    If you do, great! Move on to the next step.

    However, if you don't see that, you will likely need to wait.

    If you don't see your commit, wait a minute or so and refresh the page. Your commit simply hasn't been picked up yet by the deployment process. Refresh until you see it.

    If you do see your commit, but there's a yellow dot or spinning circle next to it, wait a minute or so and refresh the page. Your commit is in the middle of deployment. Repeat until you see the green checkmark next to it.

    If you do see your commit, but there's a red X next to it, notify your instructor. Something went wrong on GitHub's side, and you'll need to make a new commit/push in order to fix it.

  3. At this point, our submission process diverges.

    If you set up your github repository correctly (i.e. with your username followed by .github.io) AND you are using the Chrome or Edge browsers, then you can take advantage of the "Shortcut Approach" in Part 4.

    Otherwise, if you did not set up your repository correctly OR you are using a different browser like Safari (which we don't recommend for the course), you'll have to use the "Scenic Route Approach" in Part 5

Congrats! You have confirmed that your code has been deployed and is ready to be submitted. Next, move onto the submission approach that meet your criteria below.

PART 4

The Shortcut Approach

The easy way to deliver your work

  1. Again, this approach is to be used if you set up your github repository correctly (i.e. your username followed by .github.io) AND you are using the Chrome or Edge browsers.

    If either of those are not the case, then you'll have to use the "Scenic Route Approach" in Part 5 instead.

    To start, make sure you're back on the Code tab of your repository. You should see all the folders at the root level of your repository.

    Then, navigate to the folder that you want to submit.

    If you need to submit an exercise, you'll probably need to look through the "exercises" folder to find it; same for submitting a project: you'll need to find the folder you want to submit in the "projects" folder.

  2. Once you navigate into the folder you want to submit, double check that there is an index.html file in there.

    index.html is a special file; it functions as the home page for any folder, meaning it will automatically load up that page when you open the folder, even if you don't explicitly specify the file.

    Once you're sure index.html is there, select the trail of breadcrumbs at the top of the view, starting with your repository name, and continuing through to the folder name you want to submit. Then copy what you selected.

    Do NOT click the copy icon. It will not actually copy what you need.

  3. Once you've copied that, open up a new browser tab (again, in either Chrome or Edge).

    Paste what you copied in the previous step into the URL bar and hit Return/Enter.

  4. After that, you should see the same thing in the new browser tab that you saw in the preview in Visual Studio Code.

    If not, double check that your latest commit was actually deployed (i.e. has a green checkmark next to it). If it does, double check that you actually saved all the files and changes that you expect to see on the screen.

    If all is well, move on to the last step!

  5. Now that you've confirmed everything you want to submit is correct, go back up to the URL bar and copy the ENTIRE web address, starting with the "https".

    What you're copying in this step is different from the earlier step (which was a partial web address). This is complete web address, which is the only thing Canvas will allow you to submit.

    Once copied, go back to the Canvas assignment, and submit the copied URL!

Congrats! You have have successfully submitted your coding assignment using the Shortcut Approach!

PART 5

The Scenic Route Approach

For those that deliver on the path less traveled

  1. This approach is for if you did not set up your repository correctly OR you are using a browser other than Chrome or Edge, like Safari.

    To start, revisit the Deployments page.

  2. This time, we're not here to check if our commit has been deployed; we're here to grab the "home page" URL of your GitHub Pages site.

    Open the link that leads there in another tab, and keep that tab open. We're going to come back to it in a future step.

  3. Then, return to the Code part of your repository.You should see all the folders at the root level of your repository.

    Then, navigate to the folder that you want to submit.

    If you need to submit an exercise, you'll probably need to look through the "exercises" folder to find it; same for submitting a project: you'll need to find the folder you want to submit in the "projects" folder.

  4. Once you navigate into the folder you want to submit, double check that there is an index.html file in there.

    index.html is a special file; it functions as the home page for any folder, meaning it will automatically load up that page when you open the folder, even if you don't explicitly specify the file.

    Once you're sure index.html is there, click the copy icon next to the trail of breadcrumbs at the top of the view

  5. Now return to the Github Pages "Home Page" tab we had you open earlier.

    Click into the URL, add a slash (/) to the end, and then paste what was copied in the previous step.

    The result should be a complete URL, leading to the assignment folder you want to submit.

    Go ahead and hit Enter/Return to view it.

  6. After that, you should see the same thing in the new browser tab that you saw in the preview in Visual Studio Code.

    If not, double check that your latest commit was actually deployed (i.e. has a green checkmark next to it). If it does, double check that you actually saved all the files and changes that you expect to see on the screen.

    If all is well, move on to the last step!

  7. Now that you've confirmed everything you want to submit is correct, go back up to the URL bar and copy the ENTIRE web address, starting with the "https".

    What you're copying in this step is different from the earlier step (which was a partial web address). This is complete web address, which is the only thing Canvas will allow you to submit.

    Once copied, go back to the Canvas assignment, and submit the copied URL!

    8. Congrats! You have have successfully submitted your coding assignment using the "Scenic Route" Approach!
