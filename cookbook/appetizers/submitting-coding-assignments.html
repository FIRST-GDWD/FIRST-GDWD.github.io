How to Submit Your Coding Assignments

Serving Your Work to Your Instructor

PART 1

Visual Studio Code

Save Your Work!

  1. In order to submit your work, you first have to save it!

    If you see a white circle next to the name of any files in your Visual Studio Code tabs, then you have unsaved work, which will not show up when your instructor looks at it!

    So go into those files, and hit CMD+S or CTRL+S to save them.

    Once you confirm that those circles are gone, you can move on to the next step.

Congrats! Your work is saved on your computer; now it's time to start the process of moving it up to github.com!

PART 2

GitHub Desktop (The App)

Packaging Up Your Code for Delivery

  1. Our next goal is to package up your code so that it can be sent up to github.com.

    To do so, open up GitHub Desktop.

    If you've successfully saved your changes, you should see all the file you modified in the left column labeled "Changes" in GitHub Desktop.

    Confirm that this is the case. If it is not, go back to Part 1!

    NOTE: don't be alarmed if you see red or orange colors in GitHub Desktop; they are not necessarily a bad thing. Red means deletions occurred, and orange means changes occurred. Both are very common, and are only problematic if they are unexpected!

  2. Once you've confirmed that you see the files you expected, we're going to create what is called a "commit". A "commit" is essentially a snapshot of the changes you made, packaged up such that they can be sent to github.com.

    To create a commit, you'll need to fill out the Summary field in the bottom left. This field is meant to be a note to yourself about what changes you included in the commit.

    We recommend including demo or assignment names in your summary messages, like "Created code skeleton" or "fixed bulletin board project".

    Then, once you've filled out the summary field, go ahead and click the blue "Commit" button beneath it.

  3. After hitting the "Commit" button, all your changes will seem to disappear (they aren't actually gone, they've just been moved to the History tab in the new commit you just made).

    Now we need to send that commit up to github.com. We do that through a process called a "push".

    To "push" your code up there, you just need to click one of the two buttons that say "Push origin", either the black rectangular one at the top of the screen, or the round blue one in the middle of the screen.

  4. After that, the push process will run. It usually only takes a couple of seconds, but it can run longer depending on your internet connection, how many changes you pushed, and how large the files you pushed were.

    If this process takes more than 5 minutes and you're still waiting, refer to this troubleshooting page for how to resolve it.

    Then your app should look something like the screenshot to the right.

  5. Now that you've committed and pushed, your code changes should have successfully made it up to github.com, so our next step involves actually going there to find it!

    To do so, simply click the button that says "View on GitHub", which will open a browser window that leads straight to your repository on github.com.

Congrats! You have successfully committed and pushed your code! Now onto github.com to find it!

PART 3

github.com (The Website)

Finding and Submitting Your Assignments

  1. You should now be on your repository on github.com, which should resemble the screenshot on the right.

    Before anything else, you first need to check if your code can even be viewed on your own personal GitHub Pages website.

    To do so, click on the link in the bottom right to the Deployments page.

  2. The Deployments page (should) list out all your recent commits, along with their deployment status.

    You want to confirm that you see your latest commit summary, along with a green checkmark next to it at the top of the list.

    If you do, great! Move on to the next step.

    However, if you don't see that, you will likely need to wait.

    If you don't see your commit, wait a minute or so and refresh the page. Your commit simply hasn't been picked up yet by the deployment process. Repeat until you see it.

    If you do see your commit, but there's a yellow dot or spinning circle next to it, wait a minute or so and refresh the page. Your commit is in the middle of deployment. Repeat until you see it.

    If you do see your commit, but there's a red X next to it, notify your instructor. Something went wrong on GitHub's side, and you'll need to make a new commit/push in order to fix it.

  3. At this point, our submission process diverges.

    If you set up your github repository correctly (i.e. your username followed by .github.io) AND you are using the Chrome or Edge browsers, then you can take advantage of the "Shortcut Approach" in Part 4.

    Otherwise, if you did not set up your repository correctly OR you are using a different browser like Safari (which we don't recommend for the course), you'll have to use the "Scenic Route Approach" in Part 5

Congrats! You have confirmed that your code has been deployed and is ready to be submitted. Next, move onto the submission approach that meet your criteria below.

PART 4

The Shortcut Approach

The easy way to submit your work

  1. Again, this approach is to be used if you set up your github repository correctly (i.e. your username followed by .github.io) AND you are using the Chrome or Edge browsers.

    If either of those are not the case, then you'll have to use the "Scenic Route Approach" in Part 5 instead.

    If not, click the icon that looks like two documents on top of each other.

    Then, click the "New Folder..." icon that will appear when you hover over the Explorer panel.

    Name the new folder "code-skeleton", and you'll see a folder within your repository named "code-skeleton".

  2. Next, you're going to create two new folders called "css" and "images".

    To do so, right-click your new "code-skeleton" folder and select "New folder..." again

    Name the new folder "css"

    It's going to look a little weird at first. Visual Studio Code condenses folders to one line if there is only one folder inside of another.

    Don't worry, it'll look better after we add another folder in the next step.

  3. We've created the "css" folder; now let's create the "images" folder.

    To do so, right-click your new "code-skeleton" folder and select "New folder..." again.

    Make sure you right-click the actual text "code-skeleton" and not "css" or the empty space to the right!

    If you don't, you may accidentally create the "images" folder inside of the "css" folder instead, which is not what we want.

    Name the new folder "images".

    Your Code Skeleton should resemble the image on the right.

  4. Next, you're going to create your first HTML file!

    Right-click your "code-skeleton" folder once again, but select "New file..." this time.

    Name the new file "index.html".

    After creating the file, your Code Skeleton should resemble the image on the right.

    However, we're not going to stop there; we're also going to have you "write" some code in there!

  5. In truth, we're just going to have you autogenerate an HTML template, so you won't really be "writing" much code.

    Don't worry, we don't expect you to know ANYTHING about what this code is doing (yet!).

    In your new index.html file, click in the text editor for the file, and start typing the letters "html".

    A little dropdown should pop up; go ahead and select the second option for "html:5".

  6. This will generate an almost perfect empty template for writing HTML code; however, the indentation is less than ideal.

    We'll be talking more about clean code later. For now, just trust that the changes we're making now will help you out later down the line.

  7. To get started, click and drag to select everything between (and including) the <head> and </body> tags, as shown in the image to the right.

    It's okay if the line numbers of the selected code differ on your screen compared to the image.

    After selecting the appropriate lines, go ahead and hit the TAB key on your keyboard.

    This will cause all those lines we selected to be indented one level to the right, as in the second screenshot to the right.

  8. Now, you're actually going to have to write some code.

    Put your cursor at the end of the line with <title>Document</title> in it (it's probably around line 6).

    Then hit RETURN (or ENTER for PCs) to start a new line.

    On this new line, add the following line of code (feel free to copy/paste it from here into your code file):

    <link href="css/style.css" rel="stylesheet">

    When you're done, your code should look like the image to the right.

  9. We're almost done with your HTML file. Notice the little circle to the right of the file name in the top tab of the screenshot? That means the file is not saved.

    To save your file, you can do it the long way by going to the File menu, and then clicking on Save.

    Or, you can do it the faster way by using keyboard shortcuts (Cmd+S for Mac, or Ctrl+S for PC).

    This will ensure that the changes you made to the file are saved. It is important to save frequently when you code!

  10. We've almost finished your Code Skeleton. Next, we're going to add in a CSS file.

    Right-click on the "css" folder, and select the "New File..." option.

    Name the new file "style.css" this time.

    When done correctly, your Explorer should resemble the screenshot at the right.

  11. Now, double click style.css to open it up if it isn't open already. We're going to have you write (well, copy) some CSS.

    Unless you have previous experience coding, you probably won't have a clue what any of this means.

    That's okay! We don't expect you to! This is just setting you up for success later on when we make our way to CSS.

    Add the following code into the file (again, feel free to copy/paste it directly from here):

    * {
        box-sizing: border-box;
    }

    body {
        margin: 0px;
        font-family: sans-serif;
    }

    When complete, your code should look like the screenshot to the right.

    Make sure to save your style.css file as well.

    Once you do, you're done setting up your Code Skeleton!

Congrats! You have "written" your first bit of HTML code and successfully created a project template for the rest of the course!

PART 5

The Scenic Route Approach

For those that love the path less traveled

  1. Now, jump back to Github Desktop (the app, not the site).

    In the app, you should see the changes to your code-skeleton folder; in this case, the style.css and index.html files.

    (You might wonder why the 'images' folder isn't in there. Well, GitHub desktop only tracks changes to files; folders are more or less invisible to it, until a file is put inside of them.)

  2. We're going to save a copy of your changes in something called a "commit".

    A commit is basically a snapshot of the changes you made, which gets added to the repository's version control.

    Add a commit Summary in the textboxes in the bottom left of the app.

    A commit summary is basically just a note to yourself about what code you're saving. Something like the name of the assignment or project, like "code skeleton setup", will work just fine.

    Then click the [Commit to main] button to create a commit of your changes.

  3. Next, we are going to do something called a "push".

    A push is an action that, well, pushes your local commits to the remote server on github.com.

    There are two places you start a push in Github Desktop, both circled in the screenshot below. Choose either option and click it.

    PUSH WARNING 1: Make sure all image files you commit are less than 1MB in file size; otherwise, you could cause GitHub to choke when you push your commits.

    PUSH WARNING 2: If you have weak or unstable Wifi, it is strongly recommended that you create separate commits for each image you need to push, rather than including all images in a single commit.

    Github Desktop will sometimes stall if you commit and push all your images at once with weak internet, so save yourself the stress, and commit/push images one at a time.

  4. Clicking either option will push your changes to your website

    If the push was successful, the top option should change to "Fetch origin".

  5. Now return to the Github website, and go into the repository you made earlier with github.io at the end of it. Once you navigate to the main repository code screen, you should see your code-skeleton folder that you created in the middle section.

    NOTE: Github pages often times takes 5-10 minutes to actually render out your commit, so you may have to wait and then check to see if your site is live.


    Scroll down to the bottom of the right sidebar and click on "github-pages" under "Deployments".

  6. From there you will find the deployment page. There are many options you can use to view the current deployment, circled in the screenshot to the right.

    If the icon next to the top deployment is not green, then you may have to wait longer.

    If it is an orange spinning circle, your changes are still being deployed.

    If it's red, then something went wrong in GitHub; you can most likely fix it by committing and pushing again.

    Clicking on any of the circled options will take you to your homepage (which still just displays the name of your repository, from your README.md file).

  7. In order to find your code-skeleton site (a project nested in your main repository) for submission, you must add the project folder name to the end of the URL of your homepage.

    And it must match EXACTLY! No differences in case or spacing or spelling.

    Your code-skeleton project folder will only display an empty page, with the name of "Document" on the tab. That is expected, since there's no content on the page yet.

    It can sometimes take a couple minutes after pushing your code for it to actually be published on the site, so if you get a 404 error when you first try to access the URL, give it another minute or two and then try again.

    For example:

    https://username.github.io/code-skeleton/

    8. Congratulations! You just pushed your first code project to your GitHub Pages site!
